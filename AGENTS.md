# AGENTS.md

## Project
Electron music player for Windows. Entry: `main.js` (package.json `main`). Dev machine is WSL2, app runs on Windows.

- `main.js` — window, IPC (`add-folder`/`add-files`/`remove-source`/`get-library`; `scan-progress` events main→renderer), multi-source library scan (a config list of folders and/or individual files, de-duplicated, migrating the old single `libraryRoot`), ID3 tags via `music-metadata` (`title/artist/album/duration/genre/year/quality`), `media://` protocol streaming (Range/206 for seeking), config JSON; mini-player window plus `player-state`/`player-command` IPC relay between windows, and the `miniplayer-config` IPC that resizes/pins it (`setBounds` + `setAlwaysOnTop`)
- `preload.js` — contextBridge API exposed as `window.aku` (add/remove library sources + `getLibrary`, hide/restore removed songs + `setDedupe`, player-state/command, categorize, `setMiniPlayerWindow`)
- `renderer.js` — playback/queue/shuffle/repeat, favorites, playlists, search, browse views (Albums/Artists/Genres/Eras), settings modal, sidebar autohide, themes, localStorage persistence, multi-select track rows with a bulk action bar, a queue panel, and the live playlist builder; owns the `<audio>` and broadcasts player state to the mini window
- `index.html` / `style.css` — UI (default `red` palette: `#000000`, `#830000`, `#BC0202`, `#FF0000`; alternate `teal`/`ocean`/`sage`/`forest`/`regal`/`terracotta` themes via `:root[data-theme=…]`; `terracotta` is the one light theme)
- `mini.html` / `mini.css` / `mini.js` / `mini-preload.js` — compact frameless always-on-top mini player (`window.akuMini`): cover + title/artist + play/pause/next/close, optional seek and volume bars, Bar/Card/Minimal styles and a cover-only "cube" mode (click to expand). It is a remote control only: audio lives in the main renderer, so controls go through main (`player-command`) and state comes back (`player-state`, cached in `lastPlayerState` and replayed on load)
- `scripts/make-icon.ps1` — icon pipeline; `build/` — icon source + generated PNG + `installer.nsh`; `dist/` — packaging output (generated)

## Commands (must run on Windows, not WSL)
Node/npm exist only on Windows (`C:\Program Files\nodejs`). WSL interop PATH is stale, so prefix commands with a PATH set (no inner quotes — WSL interop mangles them) and use cwd on `/mnt/c`:

```
cmd.exe /c "set PATH=C:\PROGRA~1\nodejs;%PATH%&&C:\PROGRA~1\nodejs\npm.cmd install"
cmd.exe /c "C:\PROGRA~1\nodejs\node.exe node_modules\electron\cli.js ."
```

- Launching (dev): do NOT use `npm.cmd start` from WSL — the `.bin\electron.cmd` shim needs `node` on PATH. Either use the `cli.js` invocation above, or prefix with the PATH set. In a native Windows terminal (fresh session), `npm start` works normally.
- Dev workflow: `main.js` / `preload.js` / `mini-preload.js` changes need a full app restart (main-process/preload code doesn't hot-apply); renderer-only changes (`index.html`, `style.css`, `renderer.js`, `mini.html`, `mini.css`, `mini.js`) apply with Ctrl+R (default Electron menu is kept)
- Packaging: `cmd.exe /c "set PATH=C:\PROGRA~1\nodejs;%PATH%&&C:\PROGRA~1\nodejs\node.exe node_modules\electron-builder\out\cli\cli.js --win --publish never"` (equivalent to `npm run dist` / `npm run build`; same PATH caveat) → `dist\AKU-Setup-<version>.exe` + `dist\AKU-Portable-<version>.exe`. `--publish never` is required: electron-builder otherwise "implicitly publishes" when built from a git tag and fails without a `GH_TOKEN` (assets are attached by the release workflow instead)
- Electron 44 has **no postinstall download**, so `package.json` declares `"postinstall": "node node_modules/electron/install.js"` and a fresh `npm install` now fetches the binary automatically. With `--ignore-scripts`, run it by hand: `cmd.exe /c "C:\PROGRA~1\nodejs\node.exe node_modules/electron/install.js"`
- npm 11 `allowScripts` blocks `electron-winstaller`'s postinstall by default; harmless for the targets used here (nsis/portable)
- Never run npm inside WSL for this project — it would resolve the Linux Electron, which cannot run as the intended Windows app

## Packaging
- electron-builder 26, targets `nsis` + `portable`, config in `package.json` → `build`
- `nsis` = the Windows installer (`AKU-Setup-<version>.exe`): assisted (`oneClick: false`), per-user by default, lets the user pick the install folder (`allowToChangeInstallationDirectory`) and whether to create a desktop shortcut (see below). Installs to `%LOCALAPPDATA%\Programs\AKU` with Start Menu / Desktop shortcuts and an Add/Remove Programs entry
- `portable` = `AKU-Portable-<version>.exe`, a self-contained exe (~110 MB) that extracts to a temp folder at launch (slower start)
- Both keep settings in `%APPDATA%\aku-player`. Artifact names come from `build.nsis.artifactName` / `build.portable.artifactName`; `build.win.executableName` is `AKU`; `productName`/`name`/`appId` stay `aku-player` so the data path doesn't move. File timestamp/size of the artifact is how to confirm a fresh build
- `build\installer.nsh` is a build-time NSIS include for the `nsis` target (auto-discovered, **not** in `build.files` and **not** packaged). It adds a "Create a desktop shortcut" checkbox via the `customPageAfterChangeDir` hook; because electron-builder's `createDesktopShortcut` is all-or-nothing, the page's choice is enforced in `customInstall`, which deletes the shortcut (`$newDesktopLink`) when the box is cleared (silent/update runs are skipped)
- `dist\win-unpacked\AKU.exe` is the unpacked build (no wrapper) — handy for quickly testing a packaged build
- `build.files` is a **whitelist**: any new runtime file (html/js/css preload) must be added there or it won't be in the packaged exe. Only `build/icon.png` is pulled from a subdir
- Icon: `build\icon.png` (512×512, transparent background) is used for the exe and the dev window (`BrowserWindow.icon`)
- Regenerate icon: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts\make-icon.ps1` — decodes `build\icon-source.webp` via WIC, center-crops, scales to 512, flood-fills border-connected white to transparent (inline C# in the script)

## Data locations
- Config: `%APPDATA%\aku-player\config.json` (remembers `sources`, `dedupe`, `hidden`, `dupesKept`; migrates the legacy `libraryRoot`)
- Renderer state (favorites/playlists/volume/view, plus `settings`, `sidebarPinned`, `miniMode`, `lastPosition`): localStorage inside the Electron profile (= userData dir)
- Caches: `%LOCALAPPDATA%\npm-cache`, `%LOCALAPPDATA%\electron`, `%LOCALAPPDATA%\electron-builder` (approved standard locations)

## Conventions / gotchas
- Track IDs are `sha1(path).slice(0, 16)` — favorites/playlists survive rescans as long as file paths are unchanged
- Track rows: a plain click starts playback; Ctrl/Cmd-click toggles selection and Shift-click selects a range (heart, `+` and `⊘` excluded). A non-empty selection shows the floating `#sel-bar` (Play / Queue / Heart / Unheart / Add to playlist / Remove from queue / Remove / Clear). There is no double-click handler
- Library sources live in `config.json` as `sources: [{ path, type: 'folder'|'file' }]`; `get-library`/`add-*`/`remove-source` all return `{ sources, tracks, hidden, dedupe, duplicates, ignored, dupesKept }` (or `null` when empty). Main owns the list (files are de-duplicated across overlapping sources); the renderer just re-applies the returned payload via `applyLibrary()`. The old single `libraryRoot` is migrated on read
- Duplicate handling lives in main, not localStorage: `config.dedupe` (default on) collapses tracks sharing a `dupeKey` (normalized `artist|title`, but only when there is a real title **and** a real artist — the `unknown`/`Unknown artist` fallback and untitled files are never merged) down to the best copy by `qualityRank` (lossless → bitsPerSample → sampleRate → bitrate; tie = first found). `scanLibrary` returns `{ tracks, duplicates, ignored, dupesKept }` and fills `trackIndex` (`id → { path, title, artist }`), which backs the hide/restore IPCs. `config.dupesKept: [path]` pins copies the user restored (all pinned copies are kept, plus the best non-pinned one per key); IPC `restore-duplicates`/`ignore-duplicates` (ids → paths) add/remove pins. Settings → Library has `{ type: 'dedupe' }` (`buildDedupeRow`, `setDedupe`) and `{ type: 'duplicates' }` (`buildDuplicatesRow` — a compact "Duplicates" row with an ignored/restored count and a **Manage duplicates…** button that opens the `#dupes-overlay` (`openDuplicates`/`closeDuplicates`/`renderDuplicates`), which holds the "Ignored duplicates" list (Restore/Restore all) and the "Restored duplicates" list (Ignore again)); the status line reports "N duplicates ignored"
- Remove-from-library is non-destructive: `config.hidden: [{ path, title, artist }]` (de-duped by path, applied as a hidden set in `collectAudioFiles` so hidden files are never read). IPC `hide-tracks` (ids → paths via `trackIndex`), `restore-tracks` (paths), `restore-all-hidden`; each saves config and returns a fresh payload. The `⊘` row action and the selection bar's Remove call `hideTracks()` (behind a `confirm()`); Settings → Hidden songs (`buildHiddenRow`) lists them with Restore / Restore all
- Playlist shapes: manual `{ name, trackIds }` (from the `+` button), auto genre `{ auto, genre, genreKey }` (genre maker), and live builder `{ live, sources: [{ type, key, label }], extraIds }`. `playlistTrackIds(pl)` recomputes live playlists via `computeLiveTrackIds` (union of sources in order + extras, de-duped); `recomputeLivePlaylists()` runs after every scan/categorize. `sources[].type` is `genre|album|artist|era|year`, and keys must match `genreGroups` (lowercased genre), `albumGroups` (`album\u0000artist`), `artistGroups` (name), `eraGroups` (`d2010`/`unknown`) or the year string
- The queue panel (`#queue-btn` → `#queue-panel`, `renderQueue()`) mirrors `state.queue`; `addToQueue` inserts after the current track and `removeFromQueue` (selection bar) drops tracks. The queue is intentionally not persisted
- Shuffle is a generated play order, not per-track randomness: `buildQueue(context, currentId)` stores the unshuffled context in `state.queueOrigin` and, when `state.shuffle` is on, `state.queue = shuffledFrom(context, currentId)` (Fisher–Yates, current track first). `playNext`/`playPrev` then walk the queue linearly (with the usual repeat/wrap and the >3s restart rule), so Previous returns to what actually played; toggling shuffle rebuilds from `queueOrigin` (or restores it). Queue-item clicks call `playTrack(id, null, true)` (keepQueue) so jumping doesn't reshuffle
- Mini player is opened from `#mini-btn` in the player bar; main owns the audio, the mini window only reflects state and sends commands
- The mini window is created `resizable: false` but is resized programmatically through `miniplayer-config` → `setBounds` (and pinned via `setAlwaysOnTop`); its `minWidth`/`minHeight` are 40 so cube mode (80×80) fits. If a future Electron build ignores `setBounds` on non-resizable windows, switch it to `resizable: true` (frameless windows show no user resize grips)
- Display name is `AKU` (sidebar brand, window titles; the red first letter comes from `.brand::first-letter`). Internal id stays `aku-player` (`app.setName`, package.json `name`/`productName`/`appId`) so `%APPDATA%\aku-player` stays put; only the packaged exe name is `AKU` (via `build.nsis.artifactName` / `build.portable.artifactName` + `build.win.executableName`)
- Track objects include `quality` (`container, codec, bitrate, sampleRate, bitsPerSample, channels, lossless`) from music-metadata `format`; `null` if parsing failed. Shown as a pill + popover in the player bar (`#quality-btn`, `#quality-popover`)
- Track objects include `genre` (`string[]`, cleaned from `common.genre`: split on `;` `,` `/`, de-duped case-insensitively, numeric-only dropped). The genre maker (`#genre-maker` → `#genre-popover`, next to the playlists `+`) creates one auto playlist per genre: multi-genre tracks join every genre, no-genre tracks are skipped, a min-tracks filter hides small genres. Auto playlists carry `{ auto: true, genre, genreKey }`, are named `Genre: <name>`, and are refreshed in place on re-run (unchecked genres are removed; manual playlists are never touched)
- Genre categorizer (`#categorize-btn`, sidebar) fills missing genres by querying the iTunes Search API (`entity=song`, takes `primaryGenreName`), rate-limited to ~1 req/1s. It runs in main (`categorize` IPC, `categorize-progress`/`categorize-cancel` events) and results are merged into in-memory `track.genre` (file tags are never modified). Results are cached in `%APPDATA%\aku-player\genre-cache.json` keyed by normalized `artist|title` and re-applied during scan. This is the app's only outbound network use. (MusicBrainz was evaluated first: recording-level genres were reliably empty and artist-level genres far too noisy)
- Scan extensions: mp3, m4a, aac, ogg, oga, opus, wav, flac. `.wma` is intentionally excluded — Chromium cannot decode WMA (nor ALAC/APE/WavPack/DSD)
- Audio is streamed via custom `media://` scheme in `main.js`; do not switch to `file://` or relax `webSecurity` — CSP in `index.html` only allows `media:` for audio/covers
- Both windows use `contextIsolation: true` + `sandbox: true` with a preload (`window.aku` / `window.akuMini`); add APIs via `contextBridge`, never expose Node. Renderer CSP is `default-src 'none'`, so the renderer cannot fetch externally — do outbound network in `main.js` (see categorizer)
- `window.prompt` is unavailable in Electron; playlist creation uses an inline input (`#new-playlist-input`)
- No tests or linter configured; `.github/workflows/ci.yml` runs `node --check` on the JS entry points as a light parse gate
- User constraint: keep all changes inside this folder unless explicitly approved

## Views & settings
- Sidebar nav: Library, Favorites, then browse views Albums/Artists/Genres/Eras. Browse pages show a cover grid (Albums) or list rows (Artists/Genres/Eras); clicking one opens a detail view (`state.view.type` `album`/`artist`/`genre`/`era` with `name`), which reuses the normal track rows. Search filters group names on browse pages, tracks on list/detail views (`renderMain()` routes). `renderer.js` helpers: `albumGroups()` (key `album\u0000artist`), `artistGroups()`, `eraGroups()` (decade label from `track.year`, newest-first, `Unknown` last), plus the existing `genreGroups()`
- Track objects include `year` (from music-metadata `common.year`, falling back to `common.date`); `null` when absent. Eras group by `floor(year/10)*10` → e.g. `2000s`; year-less tracks land in `Unknown`
- Settings is a modal overlay in the main window (`#settings-overlay`, built by `renderSettings()` from `settingsSections()`), opened by the topbar gear (`#settings-btn`). Every option lives in `state.settings` (persisted in the localStorage blob) and is applied by `applySettings()` — except the Library dedupe/hidden rows, which live in `config.json` and re-scan via `setDedupe`/`restoreTracks`. Toggles: theme, sidebar auto-hide, browse sections, genre tools, favorites, quality indicator, track rows (Comfortable / Compact / No covers), resume playback, confirm playlist delete, shuffle/repeat buttons, and the mini-player options below. `settings.rowDisplay` replaced the old separate `coverArt`/`compactDensity` toggles; `restore()` migrates the legacy keys
- Music sources are managed from Settings → Library (the `{ type: 'sources' }` row → `buildSourcesRow`) and from the topbar `Add music` button, which opens the `#add-menu` popover (`Add folder…` / `Add files…`). Settings → Library also holds the `{ type: 'dedupe' }` toggle, the `{ type: 'duplicates' }` ignored/restored list and the `{ type: 'hidden' }` restore list
- Playlist builder (`#playlist-builder` → `#builder-overlay`; `openBuilder`/`renderBuilder`/`saveBuilder`): tabs for Genres/Albums/Artists/Eras/Years, a chip list of chosen sources (draggable to reorder), a per-tab filter, a hand-picked-track search, and a Live checkbox. Editing an existing live/source playlist (the `✎` in the sidebar) reuses the same modal; plain `+` playlists are not edited there
- Sidebar autohide: when `settings.sidebarAutoHide` is on the sidebar collapses via `margin-left` (`html[data-sidebar="hidden"]`); a left-edge `#sidebar-handle` peeks it open (`html.sidebar-peek`), and `#sidebar-toggle` (topbar) pins it (`state.sidebarPinned`, persisted). Menu button + handle are hidden when autohide is off
- Themes: `state.settings.theme` sets `document.documentElement.dataset.theme`; `:root[data-theme="teal"|"ocean"|"sage"|"forest"|"regal"|"terracotta"]` blocks in `style.css` and `mini.css` override the palette vars (default `red` uses the plain `:root`; `terracotta` is a light theme). `--accent-text` (default `#fff`) colours the text on filled `.accent-btn`/`#repeat-one` so light accents stay readable. Theme travels to the mini window inside the `player-state` snapshot
- Mini player: `state.settings.miniStyle` (`bar`/`card`/`minimal`), `miniSeek`/`miniVolume` add seek/volume rows, `miniStartCube` starts it collapsed, `miniAlwaysOnTop` toggles pinning. `state.miniMode` (`full`/`cube`) is a cover-only square; the cube button collapses, clicking the cover expands. `miniWindowSize()` computes the size and `applyMiniWindow()` sends it via `setMiniPlayerWindow` → main `miniplayer-config` IPC (`setBounds` + `setAlwaysOnTop`). Seek/volume/cube controls ride the existing `player-command` relay (`mini-mode` handled in `handlePlayerCommand`)
- Resume playback (`settings.resumePlayback`): `state.lastPosition` is saved with the state; on launch `loadLibrary()` sets `audio.src` and restores the position via the `pendingResume` path (no autoplay)

## Install & distribution
- License is MIT (`LICENSE`); `package.json` carries `license`, `repository`, `homepage`, `bugs` and `engines` (`node >=20`), and `.nvmrc` pins 20
- From source: `git clone` → `npm install` → `npm start` (the `postinstall` fetches Electron); `npm run dev` is an alias of `start`
- Source installer: `scripts/install.ps1` — clones into `%LOCALAPPDATA%\AKU-PLAYER`, installs deps and adds Desktop/Start Menu shortcuts (pointing at `node_modules\electron\dist\electron.exe`, or `dist\win-unpacked\AKU.exe` with `-Build`); `-Uninstall` reverses it. Served from the repo raw URL
- Releases: `.github/workflows/release.yml` builds both the installer and the portable exe on any `v*` tag (windows-latest, Node 20, `npm run dist`) and attaches `dist/AKU-Setup-*.exe` and `dist/AKU-Portable-*.exe` to the GitHub release. To publish, bump `package.json` `version` and push a matching tag
- `.gitignore` excludes `node_modules/` and `dist/`; `build/` (icon + installer.nsh) is committed. `.gitattributes` forces CRLF for `.ps1`/`.cmd`/`.bat`/`.nsh`
